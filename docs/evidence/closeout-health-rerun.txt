## Corrected configuration and test data

The initial 503 came from starting `mysql_test` with the empty `DB_PASSWORD`; the local MariaDB credentials are configured under `DB_MARIADB_*`. Runtime now uses `mariadb_test`. For PHPUnit/Playwright, which explicitly select `mysql_test`, `DB_PASSWORD` was supplied from the local `DB_MARIADB_PASSWORD` setting without printing it.

Five already-pending additive migrations were applied only to `erp_acceptance_tests`: `000010` through `000014`. The first acceptance seed attempt exposed the missing `000010` column and stopped; after migrations, Playwright's global setup completed its seeders.

The acceptance database contained 207 generated `probe_[a-f0-9]{8}` accounts left by API tests, which filled the login-options 200-row cap. They were marked inactive (not deleted) with an exact username-pattern predicate guarded by `DATABASE()='erp_acceptance_tests'`. This made the seeded E2E users visible in the test login list.
