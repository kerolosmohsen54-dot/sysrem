## ما يحتاج متابعة

1. أداة `contract:check` وجدت هذه المسارات في الواجهة ولم تجدها في `backend/docs/openapi.yaml`: `GET /reports/profit-distribution`، `GET /invoice-issuers`، `GET /customers/{customerId}/last-prices`، و`POST /invoices/{documentId}/printed`. تحققت من وجود handlers والمسارات الأربعة في Laravel؛ هذه فجوة توثيق API وليست مسارات مفقودة من التطبيق.
2. لم أجد اختبارات Backend مباشرة مخصصة لـ`invoiceIssuers` و`customerLastPrices` و`markInvoicePrinted`. يوجد اختبار واجهة لمحاكاة قائمة جهات إصدار الفواتير، لكن لا يوجد تحقق من تنفيذها على الخادم. استدعاء الطباعة موجود في `InvoicePrintPage`، لكن اختبار الشاشة الحالي لا يضغط زر الطباعة ولا يثبت تسجيل `printed_at`. أداة الفحص لا تثبت وجود عطل؛ التغطية هنا غير كافية لإثبات السلوك.
3. تحقق الوصول عبر عنوان LAN أُجري من نفس الكمبيوتر فقط. لم أختبر هاتفًا فعليًا؛ جدار حماية Windows رفض إضافة قاعدة المنفذ دون صلاحية مسؤول.
4. تشغيل CLI الافتراضي بـPHP 8.2 لا يناسب متطلبات الباك إند. الاختبارات نجحت عند استخدام PHP 8.3.33 الموجود في Laragon.
5. اختبار دخول الواجهة استخدم API mock، واختبارات المصادقة في الباك إند آلية. لم أستخدم بيانات دخول حقيقية، لذلك دخول حسابك الفعلي غير مؤكد من هذه المراجعة.
