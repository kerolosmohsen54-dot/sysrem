# تدقيق فجوات الواجهة الأمامية مقارنة بالمرجع

**تاريخ المراجعة:** 2026-10-29  
**ملف المرجع:** `frontend/reference/precision-slate-erp-v43__3_ (1).html`  
**النطاق:** مقارنة الشاشات والنماذج والتنقل الظاهرة في ملف المرجع بواجهات React الحالية فقط.

> هذا التدقيق لا يقيّم API أو الخادم أو قاعدة البيانات أو نجاح حفظ البيانات. «موجودة» تعني أن للمستخدم شاشة أو تدفق واجهة متاحًا في التطبيق. إذا كانت الشاشة مجرد انتظار أو نافذة تجريبية أو تبويبًا فارغًا، فهي «جزئية» وليست ميزة مكتملة.

## الخلاصة

معظم المجالات التشغيلية الأساسية لها صفحات حالية: العملاء، الطلبات، الفواتير، التحصيل، المرتجعات، التسليم، المنتجات والمخزون، الحاويات، الخزينة، المصروفات، الشركاء، المشتريات، التقارير، والإدارة. الفجوات الأوضح هي وظائف إضافية يعرضها المرجع ولا يوفّر التطبيق لها تدفق واجهة مكتملًا.

### وظائف مرجعية لا توجد لها شاشة/تدفق حقيقي في الواجهة الحالية

- ميزانية المصروفات.
- المصروفات المتكررة.
- مقارنة شهر بشهر.
- توقع السيولة.
- الأموال المنتظرة وخطط أقساط الشركاء.
- طباعة ملصقات الباركود وإدارة المسح من شاشة مستقلة؛ البحث بالباركود موجود داخل إدخال الفاتورة فقط.
- ملاحظاتي الشخصية.
- واجهة مرفقات العميل، وسجل العميل الموحّد بتبويبات الطلبات والفواتير والمدفوعات.

### وظائف تظهر في التطبيق لكن واجهتها جزئية أو انتظار

- لوحة التحكم: بطاقات أرقام موجودة، لكن الرسوم والمخزون الحديث والنشاط والتنبيهات وفلاتر الفترة غير معروضة كبيانات فعلية؛ مواضعها حالات انتظار.
- المالية: صفحات الخزينة والمصروفات والتحويلات وغيرها موجودة، لكن الصفحة الرئيسية أقرب إلى دليل روابط من لوحة مالية تعرض حركة موحدة؛ دليل الحسابات والتسويات شاشتان انتظار.
- التقارير: توجد وجهات تقارير فعلية، لكن العدد والتفاصيل أقل من النماذج التي يدّعيها المرجع؛ تقرير المالية الحالي ملخص مؤشرات وليس واجهة قوائم مالية تفصيلية.
- المرتجعات: التدفق المتاح مرتبط بفاتورة أصلية؛ لا يظهر اختيار طريقة المعالجة (استرداد نقدي/رصيد عميل/استبدال)، كما أن شاشة المرتجع المنفصلة الموجودة في المصدر غير موصولة بمسار التطبيق.
- الطلبات: تبويب الحجز موجود اسميًا، لكنه يعرض رسالة بأن الحجز غير متاح.
- التسليم: توجد شاشة إنشاء وتفاصيل، لكنها لا تعرض تدفق التسليم الجزئي أو مسح QR أو خطوط كميات التسليم مثل المرجع.
- الاستيراد والملخص اليومي: العنصران يفتحان نافذة تجريبية محلية، وليس شاشة وظيفية مكافئة لشاشات المرجع.
- إدارة المستخدمين: إضافة/تعديل المستخدم موجودان، لكن إدخال الأدوار نصيًا لا يوفّر مصفوفة صلاحيات مرئية أو صفحة ملف شخصي/أمان مماثلة.

## معيار الحالات

| الحالة | معناها في هذا الملف |
|---|---|
| موجودة | توجد شاشة/عملية React قابلة للوصول تغطي الفكرة الأساسية. لا يعني ذلك تطابق كل التفاصيل المرئية مع المرجع. |
| جزئية | توجد صفحة أو عنصر واجهة، لكن أقسامًا أساسية فارغة أو انتظار أو ناقصة مقارنة بالمرجع. |
| غائبة | لا يوجد في التطبيق الحالي تدفق واجهة مستخدم مكافئ. |
| موجودة مع اختلاف | الفكرة موجودة، لكن المرجع يعرضها في تبويب/شاشة مختلفة أو بتفاصيل أوسع. |

## قائمة الفجوات مرتبة حسب وضوحها

### غائبة كواجهة

1. ميزانية المصروفات والتنبيه قرب/تجاوز السقف.
2. المصروفات المتكررة.
3. مقارنة شهر بشهر.
4. توقع السيولة.
5. الأموال المنتظرة وخطط أقساط الشركاء.
6. صفحة مستقلة لطباعة ملصقات الباركود وإدارة المسح.
7. ملاحظاتي الشخصية.
8. واجهة مرفقات العميل.
9. سجل موحد داخل ملف العميل لتبويبات الطلبات والفواتير والمدفوعات.

### موجودة جزئيًا وتحتاج استكمال واجهتها

1. لوحة التحكم: مخطط الفترة، مؤشرات المخزون التفصيلية، النشاط الحديث والتنبيهات.
2. الطلبات: عرض الحجوزات بدل placeholder.
3. المرتجعات: توحيد مسار الإنشاء وإظهار خيارات المعالجة المرجعية إن كانت معتمدة ضمن المنتج.
4. التسليم: خطوط الكميات، التسليم الجزئي، QR، واختيارات النقل الظاهرة في المرجع.
5. التقارير: توسيع الفهرس والتفاصيل المرئية، مع عدم تسمية ملخص المؤشرات كقوائم محاسبية كاملة.
6. المالية: لوحة مالية تعرض ملخص الحركة بشكل مباشر بجانب روابط الأقسام.
7. دليل الحسابات والتسويات: استبدال صفحات الانتظار بواجهات فعلية إذا كانت ضمن النطاق المعتمد.
8. الإعدادات: تنظيم الحقول في أقسام مرئية، وإظهار حقول المرجع التي يحتاجها المستخدم فعلًا.
9. إدارة المستخدم: واجهة اختيار دور/صلاحيات مقروءة بدل إدخال رموز الأدوار كنص.
10. الاستيراد والملخص اليومي: تحويل النافذتين التجريبيتين إلى شاشات لها عناصر المرجع، أو إبقاؤهما معلّمتين بوضوح كتجريبيتين.

## ملاحظات تمنع احتساب عناصر غير مكتملة كميزات

- ملف المرجع نموذج HTML تفاعلي كثيف، وبعض إضافاته تُنشئ شاشات من JavaScript بعد تحميل الصفحة. العدد الذي يعلنه مركز التقارير (28 تقريرًا/6 فئات) لا يطابق البطاقات النهائية الظاهرة في DOM (5 فئات).
- توجد روابط مرجعية إلى `settings` و`expenses` و`cashiers` دون أقسام `sec-settings` و`sec-expenses` و`sec-cashiers` في DOM النهائي. لذلك لا أحتسب هذه الروابط المكسورة على أنها شاشات مرجعية مكتملة.
- التقييم مبني على قراءة ملف المرجع ومكونات ومسارات React، وليس اختبار نقر مرئيًا لكل شاشة أو مقارنة صور على مقاسات متعددة.
